# New API integration

Actvero uses New API for supplier connections, model mappings, routing, pricing and native consumption logs. Actvero owns organization access, member point conversion, admission windows and its settlement ledger. The browser uses Actvero's authenticated control-plane adapter; desktop clients receive short-lived Actvero resource tokens. Management tokens, relay keys and supplier credentials remain server-side.

Exact model metadata may include the optional Actvero `display_name` field. The native metadata adapter reads and writes it through the existing organization-scoped member catalog `name`, strips it before forwarding to New API, and includes it in the editor's revision check. An empty value falls back to the invocation ID. Presentation-only drafts remain disabled; edits to an existing member model preserve its resource identity, access policy and execution configuration. Public metadata synchronization does not own or overwrite this name. Native model identifiers, channel mappings and pricing keys remain unchanged.

## Deployment and organization ownership

Fresh configurations generated by `scripts/docker-env.sh` or `scripts/env.py` enable the Compose `gateway` profile. `docker compose up --build -d --wait` starts the pinned gateway alongside Actvero, creates a dedicated bridge service credential, and waits for gateway health before starting the app. The gateway has its own persistent `newapi-data` volume and no published port. Bootstrap secrets are generated into the ignored, private `.env`; existing files are never overwritten.

One deployment connection serves every organization. Actvero supplies the authenticated organization's UUID to a root-only bridge; the browser cannot select a different owner. The gateway provisions a private technical user, fixed-group relay token and namespace. Channels, model metadata, vendors, prefill groups and pricing belong to that namespace. Same public model names may have different suppliers and prices. Names and identity mappings are translated at the boundary; internal identifiers remain in immutable billing evidence. There is no platform-shared channel pool.

The overlay adds a native ownership table and additive schema changes for internal identifier lengths. It retains native provider adapters, mappings, routing, metadata synchronization, price versions and consumption logs. The bridge requires the explicit root-only `actvero:write` capability. Its credential cannot use ordinary global option APIs. Organization administrators never receive that credential or supplier keys. Platform-operator references do not grant gateway administration; an ordinary active organization administrator membership is required.

### Separate deployment

Build the same compatible gateway from the repository root:

```sh
docker build -t actvero-newapi:local integrations/newapi
```

Run it with persistent `/data`, a stable random `SESSION_SECRET`, `ACTVERO_ORGANIZATION_ISOLATION=true` and a deployment-generated `ACTVERO_BOOTSTRAP_TOKEN` beginning with `nap_` followed by at least 64 random hexadecimal characters. Store secrets in a private environment file or a secret manager. The first startup creates a dedicated service principal, leaving existing administrators unchanged. Repeated startup keeps the same credential. A changed secret is rejected; rotate the existing native personal access token explicitly rather than using restart as a rotation mechanism.

Configure Actvero using just the fixed gateway origin and service credential:

```dotenv
COMPOSE_PROFILES=
ACTVERO_NEWAPI_BASE_URL=https://gateway.example.com
ACTVERO_NEWAPI_MANAGEMENT_TOKEN=replace-with-the-bridge-service-credential
```

Clearing the profile leaves the external gateway lifecycle independent of Actvero. The configured fixed origin is trusted by the deployment operator and is automatically allowed for Actvero's gateway transport. Other organization-supplied model endpoints retain their separate network policy. A stock New API image without this repository's extension cannot serve the organization bridge. Existing externally managed instances may issue an `actvero:write` personal access token manually instead of using bootstrap.

The managed service uses a separate control-plane IP request allowance (`ACTVERO_NEWAPI_CONTROL_RATE_LIMIT`, default 36,000 per minute), because requests from all organizations originate at the Actvero service. For an external instance, size New API's `GLOBAL_API_RATE_LIMIT` and `GLOBAL_API_RATE_LIMIT_DURATION` for the combined workload; its stock 360 requests per 180 seconds can throttle a shared service. This is separate from Actvero member quota policies.

Organization-managed upstreams use public destinations by default. In the gateway process, `ACTVERO_EGRESS_PRIVATE_TARGETS` can explicitly allow comma-separated `host:port` targets for trusted internal providers. For the managed service use `ACTVERO_NEWAPI_EGRESS_PRIVATE_TARGETS`. The dialer validates DNS answers and pins the destination when connecting. Organization channel proxy settings are rejected. Configure deployment networking rather than delegating arbitrary private-network access to organizations.

### Existing dedicated connections

The old `ACTVERO_NEWAPI_CONNECTIONS` format remains available for existing dedicated-instance deployments. It still rejects reuse of an origin across organizations and cannot be combined with the shared connection format. No tenant is automatically assigned an existing gateway's unowned resources.

To adopt a formerly single-organization instance, stop Actvero and the gateway, and back up both databases, gateway `/data`, environment secrets and Actvero's accounting outbox. In the compatible gateway, set `ACTVERO_ADOPT_ORGANIZATION` to the original Actvero organization UUID and `ACTVERO_ADOPT_RELAY_TOKEN_ID` to its original fixed `default`-group relay token ID. Start the gateway before switching Actvero to the shared connection. Adoption requires an otherwise unassigned instance and rejects per-channel proxies and automatic/cross-group relay tokens.

Adoption preserves channel/model/vendor IDs, copies prices and group ratios into the namespace, rebuilds channel abilities and records the original relay token for historical log reconciliation. Original logs and credential values remain immutable; the old relay token is disabled for future calls. Repeating the same adoption is idempotent. After verification, remove the one-time adoption environment variables. Restore the matching full backup when rolling back; switching environment variables alone does not undo data ownership changes.

The server deployment helper builds the gateway before stopping running services. In managed mode its consistent backup includes the stopped gateway's complete `/data` directory. External gateway backups and version upgrades remain the external operator's responsibility and must be coordinated with Actvero backups. Never discard the gateway volume during an ordinary upgrade.

## Points and reservation

The preflight handler reads the live effective native pricing and relay-token group ratio. Legacy ratio prices use New API's existing expression conversion. The bounded analysis operates on the native validated expression: chat text, tools and inline images use the native relay token counter, while output uses the approved per-request maximum. Image estimates follow native model rules and media-count settings. Remote URLs and other media retain the context-capacity bound without fetching remote files. All conditional price branches are included, including time-dependent and request-dependent multipliers. Unsupported task quantities, unbounded arithmetic, non-finite values and quota overflow reject admission. A known zero price can reserve zero; unknown prices cannot.

Actvero serializes member admission, reserves the returned amount using the current point conversion and retains the native pricing version, expression hash, quantity limits and group snapshot. Final settlement uses the matching native consumption log and the admission-time conversion. Missing or ambiguous billing evidence retains the reservation for review. Quota windows remain tied to admission time, including late settlement.

The estimate is conservative and may reserve more than the eventual charge. Input tokenization is an estimate rather than confirmed usage. It is not a supplier spending guarantee: concurrent native price/group changes, channel parameter overrides and provider-reported usage can exceed the estimate. Actual confirmed charges are retained rather than clamped; additional calls then use the remaining quota. Native channel retries remain owned by New API. Actvero does not replay an uncertain invocation to recover a missing bill.

## Maintain and verify

Before changing the upstream version, review `apply.py` anchors, token-scope guards, expression semantics and native log evidence. Run the native `TestActvero` and `AdmissionBound` tests, then Actvero's isolated database and native gateway contract tests. `backend/tests/test_shared_model_gateway.py` optionally uses a disposable gateway configured through `ACTVERO_TEST_SHARED_NEWAPI_URL` and `ACTVERO_TEST_SHARED_NEWAPI_TOKEN`; never point it at an organization's live gateway. `scripts/test-gateway-deployment.py` renders managed and external Compose contracts without starting services. The integration test creates and removes its own temporary channel and pricing fixture; it does not use supplier credentials.

The backend capability snapshot is generated separately with `node frontend/scripts/export-model-capabilities.mjs`, using the locked pi-ai dependency. It supplies advisory capabilities for real discovered routes and never replaces an upstream model-list response. Deployments do not read a sibling desktop checkout.

Exact Ark Agent Plan templates also use the separately reviewed `backend/app/modules/model_gateway/data/ark-plan-capabilities.json` profile. It records official sources and verification date, resolves the actual mapped upstream name, and retains unknown optional features instead of inventing support. The current snapshot covers 15 text models; models without verified effort controls expose only the supplier default. The provider identity is derived server-side from the full canonical routes and origin, without forwarding raw channel settings. This profile never applies by name alone to unrelated custom endpoints. Ark pass-through requests use `max_completion_tokens` to bound both reasoning and answer output; other native adapters retain their existing `max_tokens` input.

### Ark Agent Plan template

The provider picker includes an Ark Agent Plan preset using native Advanced Custom routes. Chat and Anthropic Messages use the plan-specific paths; Responses requests use New API's native Chat conversion. Both creation and editing retain the same native form. Customizing the routes makes the channel an ordinary Advanced Custom connection.

Agent Plan has no data-plane `/models` endpoint, and its control-plane `ListArkAgentPlanModel` requires AK/SK rather than the Plan API key. The exact preset reads the text-model support table in [Ark's public Plan documentation](https://docs.volcengine.com/docs/ark/agent-plan-personal-plan-overview?lang=zh), with a one-hour cache and no credentials sent to the documentation host. The UI labels this as a public directory: it does not prove key-specific availability, enable member access, or include image/video-generation routes. If fetching or parsing fails, discovery reports unavailable instead of returning a built-in inventory. Other suppliers continue using native key-scoped discovery. Saved-channel discovery uses the authorized saved configuration; unsaved edits are applied after saving.

Saving the exact preset initializes unconfigured model prices from the reviewed price snapshot in `backend/app/modules/model_gateway/ark_prices.json`. The snapshot prefers ordinary Ark API online prices. Models missing from that table use explicitly labeled TRAE official reference prices; the retiring Kimi-K2.7-code retains the dated historical TRAE reference. This is the organization's member-billing reference, not Agent Plan AFP usage or the supplier's subscription cost. Existing explicit organization prices are preserved. Explicit channel model mappings let aliases receive the mapped model's reference price; display names are never guessed. The CNY list prices are normalized to native USD expressions using the gateway's configured `usd_exchange_rate` at import time; the resulting expression and native pricing version retain that conversion. DeepSeek V4.1 Flash uses Ark's Beijing peak/off-peak schedule, while Ark V4 Pro uses its fixed list price. Doubao Mini uses input-length tiers, and MiniMax M3 uses the documented combined input/output length tiers. Batch-inference prices and temporary promotional discounts are not used.

The snapshot records each source and verification date. Pricing reads label an imported expression only while its complete expression still matches the reviewed reference; a custom edit removes that provenance label. Clean pricing editors refresh after an import, while unsaved drafts retain their original version. Missing pricing is distinct from free pricing and never displays the initial zero expression as an effective price. Models outside that reviewed snapshot are not initialized; the form flags them for pricing review. Existing native prices may still apply to such models. Saving still succeeds if price import fails; the form reports that pricing needs attention. The preset never assigns zero to an unknown price. The current chat input contract accepts text and images; audio tariffs retained in the source snapshot are not imported as a partially supported audio-cache expression. Cache storage fees are outside request token billing. Changes to published list prices require a reviewed snapshot update and an explicit native price edit for models already configured.
