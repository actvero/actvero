# 系统架构

Actvero 由 Web 控制台、FastAPI 业务应用、PostgreSQL、Keycloak 和独立管理 CLI 组成。构建后的 Web 资源由应用托管；桌面应用通过版本化接口接入。

## 边界

Keycloak 负责认证协议、密码与 MFA。平台负责组织成员关系、资源权限、设备会话、专家/Skill 版本、额度、结算与审计。平台运营与组织管理员是不同权限边界。

多个组织可共用一套兼容 New API，通过内部命名空间、独立技术账户和固定分组令牌隔离渠道、模型、价格与账单。Actvero 始终从当前认证成员关系取得组织归属；平台运营引用不授予组织网关权限。目前只提供组织自有资源。部署可随 Compose 一起启动，也可连接独立部署的网关。

接入 New API 时，其控制面管理渠道、映射与价格，数据面负责供应商适配、路由和实际计费；Actvero 在前方校验成员权限、预留积分并核对消费日志。直接管理模式的模型适配与上游执行复用 LiteLLM SDK；MCP 集成复用 FastMCP。调用证据与计量状态由平台保存。缺失计量不得补零，响应交付不等同于已确认结算。

## 代码组织

后端按 `backend/app/modules/` 下的业务域组织；前端按 `frontend/src/features/` 组织页面，`routes/` 仅负责接入。API 的机器可读定义是 [OpenAPI](api/openapi.json)，前端类型由它生成。

历史迁移文件共同构成当前数据库初始化和升级链，不能为了精简仓库而移除。使用 `alembic heads` 获取实际目标版本。

## 数据与外部访问

业务和身份数据分别存储；会话和上游凭据使用持久加密配置。公网模型与 MCP 请求采用各自的网络策略，内网访问需要明确配置。头像、Skill 包等业务资产与运行中的账务 outbox 需要纳入备份。

## 客户端分发

`object_storage` 提供平台级加密存储配置和 S3 连接能力，供不同业务模块复用。`client_distribution` 扩展既有客户端版本表，维护文件、multipart 上传、持久化校验任务、发布计划与更新通道快照。Web 与 CLI 使用不同认证入口并复用领域服务；公开更新清单仅引用校验后的发布文件。操作契约见[客户端更新发布](CLIENT-DISTRIBUTION.md)。

`workbenches` 管理组织内部的工作台发布。组织管理员在「能力管理 → 工作台」上传 Actvero `.tgz` 安装包，校验后保存草稿，并可设置使用范围、发布或下架。原始安装包与版本资料分表保存在 PostgreSQL 中。每个工作台最多有一个当前发布版本，发布后保留原包和版本记录。包可在 `package.json` 通过 `dsh.actveroWorkbenchIcon` 声明包内头像。后台优先展示当前发布版本的头像，桌面目录向有权使用该版本的成员提供同一头像。接口以 [OpenAPI](api/openapi.json) 为准。

桌面端目录只列出成员获授权的当前发布版本。安装包可通过 `dsh.actveroWorkbenchPreviews` 声明最多 3 张包内静态 PNG、JPEG 或 WebP 预览图，每张最大 128 KiB，宽高均不超过 2048 像素。平台校验并保存这些图片，桌面端可在安装前按声明顺序展示。下载请求指定工作台、版本 ID 和包摘要，发布变化后须刷新目录。检查更新时会同时返回已安装版本是否仍可使用。下架或撤销授权后，目录不再列出该工作台，平台拒绝下载和后续打开检查。

需要连接业务服务的工作台可在安装包的 `package.json` 中通过 `dsh.actveroWorkbenchConfig` 声明运行配置字段。组织管理员在工作台的「运行配置」中填写服务地址等非敏感参数，并在发布前补齐必填项。配置按组织和工作台存储，同名字段在升级时沿用。桌面端使用 `workbenches:config` 资源令牌读取已获授权版本声明的字段。停用组织、撤销成员授权或下架工作台后，平台拒绝后续配置读取。
