# 知识库

本文面向组织管理员与集成开发者，用于配置解析器和模型、导入资料、检查检索结果，并根据稳定引用定位原文。

## 配置与使用

后台「知识库」提供列表、三步创建、文档处理、检索测试及设置。组织管理员可以管理知识库，成员只能读取使用范围内的资料。使用范围支持仅管理员、组织全员、指定成员与部门；部门规则沿用组织权限服务。

先在「默认配置」中选择模型网关已开放的向量模型。模型必须声明向量维度和向量空间，并具备可用渠道、价格、积分换算和额度。可选重排序模型用于重新排序召回结果。保存配置即授权知识库以保存者的模型权限执行索引与成员检索，计入该管理员的模型用量与额度；记录的调用来源为 `knowledge_index` 或 `knowledge_search`。授权人停用、移出组织、失去管理员身份或需要重新登录后，模型调用停止，需有效管理员重新保存配置。

默认模型用于新知识库。已建知识库固定向量空间，不随默认模型变更而切换。尚未配置向量模型时仍可解析、查看切片和进行关键词检索；设置默认模型后，对文档执行「重新处理」以建立向量索引。已有向量空间需要更换模型时，新建知识库重新导入，避免混合不同空间的数据。

创建流程为：

1. 填写名称、用途与使用范围。
2. 选择切片方式：智能切片填写目标字数与合并上限，长度切片填写切片长度与重叠长度。
3. 上传文件并在「处理队列」查看解析、切片和索引阶段。点击文档全屏查看原件与切片，选中右侧切片会定位并高亮左侧原文。

智能切片适配 ENGI 智慧文档的结构合并算法，不调用大模型。按文档顺序合并原始块，忽略空块、页眉页脚；当前片达到目标字数的四分之三时，后续标题开始新片。短块尽量合并，标题尽量与正文相邻，表格保持完整；合并上限是软上限，完整原始块可以超过它。模型输入上限是硬约束，超过时优先沿原始块边界拆分，再沿句子边界拆分，必要时按字符截分，并保存每一段的原文偏移。该适配保留独立的 [LGPL 来源与许可](../backend/app/modules/knowledge/licenses/engi-rag-NOTICE.txt)。

长度切片将原文块按顺序连接，以固定字符窗口切分，重叠可跨原文段落；不使用智能模式的目标字数。窗口长度不会超过模型输入上限，重叠长度必须小于窗口；模型上限较小时重叠最多取实际窗口减一。所有长度均按字符计数，不是 Token 数。

更改库级切片设置只影响后续上传；已有文档需要单独重新处理。算法升级不自动重建已有索引，历史版本与引用继续保留。

## 文件与原文定位

| 文件 | 解析方式 | 定位与预览 |
| --- | --- | --- |
| PDF、PNG、JPEG | MinerU 官方云端 API | 页号、原始块及可用坐标；PDF.js 读取原件，支持跳页、缩放与坐标高亮 |
| TXT、Markdown | UTF-8 本地结构解析 | 段落、标题、原始行号；在原文件内容上高亮 |
| CSV | 本地行解析 | 原始记录序号；在原始 CSV 上高亮完整记录 |
| DOCX | OOXML 文本解析 | 文档段落顺序；原件可下载 |
| XLSX | OOXML 缓存值解析 | 工作表、单元格范围；不执行公式，原件可下载 |

原件内容不可修改；每次重新处理创建独立版本。切片记录原文块 ID、块内起止字符、页号或段落/单元格信息。多页切片保留全部来源。阅读器只展示原件，不提供解析文本替代视图。PDF 与图片按可识别坐标绘制高亮；TXT、Markdown 与 CSV 从不可变原件计算 Unicode 字符偏移。没有可靠坐标时仅跳页，不猜测框选范围。PDF 字体与 CMap 随应用打包，不请求公共 CDN。DOCX、XLSX 暂不提供 Office 原版式在线预览，保留原件下载。

旧索引在新版本成功前继续提供检索，历史引用仍指向原版本。删除文档或归档知识库后，所有版本的引用和原文访问立即撤销。原文接口每次重新验证当前权限，响应禁止缓存；不公开文件存储地址。

## MinerU 凭据与任务恢复

PDF 和图片会发送至 MinerU，其他支持格式在服务内解析。管理员在一个输入框中填写多个官方 Key，用逗号分隔后批量添加；也接受中文逗号。保存自动去重、加密，读取接口不返回密钥。批次超过总数上限或包含格式错误时整批不写入。请按官方服务权限与配额使用，不同 Key 不代表同账号配额增加。

批量凭据会根据 Token 中可识别的账号标记分组冷却。这些未验证字段仅用于调度，不用于认证或权限判断；无法识别账号时按 Key 分别冷却。旧接口保存的账号分组继续保留。所有 Key 最终均由 MinerU 校验权限及账号配额。

任务选择可用账号凭据。遇到 HTTP 429 时按 `Retry-After` 冷却同账号的所有 Key，随后选择其他可用账号；全部冷却时等待。401/403 会停用对应 Key。已提交的解析任务固定使用原提交凭据继续查询，不会重新创建任务。

任务提交前保存待确认标记。提交响应丢失、进程在模型调用期间退出等情形会进入「待核对」，不会自动重放可能计费的请求。管理员应检查官方任务或模型调用记录后再执行「重新处理」。普通解析失败可重试；没有可用 Key 时任务等待配置。后台任务保存在数据库中，带租约且每阶段超时受限，服务重启后继续处理未完成的确定性步骤。

当前 MinerU 适配器读取官方 ZIP 中的 `*_content_list.json`，按该格式的 0–1000 坐标转换为归一化坐标。无法识别的产物会报错，不会猜测位置。官方契约见 [MinerU API](https://mineru.net/doc/docs/) 与 [产物说明](https://opendatalab.github.io/MinerU/reference/output_files/)。

## 接口与集成边界

完整请求、响应与字段约束见 [OpenAPI](api/openapi.json)，接口前缀 `/api/v1/knowledge`，标签 `knowledge`。

| 功能 | 接口 |
| --- | --- |
| 默认模型与解析凭据 | `GET/PUT /defaults`、`POST /credentials`、`POST /credentials/batch`、`PUT /credentials/{id}` |
| 知识库管理 | `GET/POST /`、`GET/PUT/DELETE /{base_id}` |
| 文档上传与列表 | `GET/POST /{base_id}/documents` |
| 文档切片 | `GET /{base_id}/documents/{document_id}` |
| 重新处理 | `POST /{base_id}/documents/{document_id}/rebuild` |
| 文档删除 | `DELETE /{base_id}/documents/{document_id}` |
| 原件、阅读定位与解析产物 | 文档路径下的 `GET /source`、`GET /preview`、`GET /parsed-source`；阅读器不展示解析产物 |
| 检索 | `POST /{base_id}/search` |
| 稳定引用 | `GET /{base_id}/citations/{chunk_id}` |

以上管理接口使用 Web 会话；所有写入及检索 POST 需要有效 Origin 与 CSRF。平台运营身份不自动拥有组织资料访问权。上传使用二进制正文与 UUID `upload_id`，同标识同内容重试返回原文档；内容不一致返回冲突。更新设置带 `version`，重建带当前 `generation_id`，避免覆盖并发修改。

检索先限制授权知识库和生效文档，再进行关键词与向量融合，最后按需重排序。返回引用 ID、文档 ID、处理版本、来源位置与同源原件接口。桌面资源令牌不适用于这些管理接口；宿主服务使用下述显式授权的访问密钥调用。

## 宿主集成与嵌入阅读器

面向桌面端、Odoo 和其他应用的服务端集成，接口前缀为 `/api/knowledge/v1`，使用 `Authorization: Bearer avk_…`。在个人「访问密钥」中新建密钥，选择「知识库检索与原文阅读」并勾选知识库；密钥只拥有所选库的 `read` 与 `invoke`。原有模型/MCP 密钥不会自动扩大到知识库。也可通过密钥 API 分别授予只读与检索权限。

| 接口 | 权限与用途 |
| --- | --- |
| `GET /bases` | `read`；列出授权且当前成员仍可访问的库 |
| `POST /bases/{base_id}/search` | `invoke`；检索，模型用量沿用组织知识库授权 |
| `GET /bases/{base_id}/citations/{chunk_id}` | `read`；返回引用摘要、文件名、处理版本、原文位置 |
| `POST /bases/{base_id}/citations/{chunk_id}/reader-session` | `read`；传入 `parent_origin`，获取短期阅读凭证 |

长期密钥只保存在宿主后端，不传给浏览器。当前集成主体仍是该密钥所属成员，并非独立系统账号，也不会自动映射 Odoo 用户；宿主必须先检查自身用户对该资料的访问资格，再返回摘要或阅读凭证。服务端同时检查组织状态、当前成员权限、密钥范围及上游账号状态。

阅读凭证最多有效 10 分钟，绑定单个文档、引用版本、签发会话或访问密钥及一个宿主来源。接口返回 `viewer_url`、`token`、`expires_at`、`parent_origin` 和协议名。`viewer_url` 不携带凭证；来源必须是 HTTPS origin，本地开发可使用 localhost/回环 HTTP。仅 `/embed/knowledge` 放开匹配来源的 iframe 嵌入，后台页面仍禁止被框架嵌入。

宿主自行设计角标、悬浮卡片、弹窗、侧栏或全屏容器；原文阅读器只提供展示与事件，不改变宿主布局。典型流程：

1. 宿主服务检索并返回引用；客户端据此绘制角标和摘要卡片。
2. 用户点击引用后，宿主服务签发阅读凭证，客户端创建 iframe，地址为返回的 `viewer_url`。
3. 阅读器通过 `postMessage` 发送 `ready`。宿主校验 `event.origin` 与 `event.source`，向该 iframe 发送 `init`，载荷包含短期 `token`。
4. 阅读器读取原件并定位高亮。`expand`、`close` 由宿主决定如何处理，`clear` 可主动清空阅读内容。

所有消息包含 `protocol: "actvero.knowledge.v1"`；禁止使用通配符目标来源。宿主初始化代码示意：

```javascript
const viewerOrigin = new URL(grant.viewer_url).origin;
function receive(event) {
  if (event.origin !== viewerOrigin || event.source !== frame.contentWindow) return;
  if (event.data?.protocol !== "actvero.knowledge.v1") return;
  if (event.data.type === "ready") {
    frame.contentWindow.postMessage(
      { protocol: "actvero.knowledge.v1", type: "init", token: grant.token },
      viewerOrigin,
    );
  }
  // expand / close / error 交给宿主容器处理。
}
window.addEventListener("message", receive);
frame.src = grant.viewer_url;
// 宿主销毁容器时移除监听器，并清除内存中的 grant。
```

阅读器不依赖第三方 Cookie；凭证仅在组件内存，HTTP 请求使用 Bearer。原件与定位接口每次重新鉴权；阅读器每 30 秒复核一次，失效后移除内容。退出原签发会话、撤销密钥、调整成员权限或归档资料都会阻止后续读取；已经下载到用户设备的数据无法远程收回。凭证过期或 `reader_unavailable` 时，宿主重新鉴权并签发凭证，不应无限重试旧凭证。

消息类型：宿主发送 `init`、`clear`；阅读器发送 `ready`、`loaded`、PDF 的 `page`、`expand`、`close`、`error`。不接受任意文件 URL、HTML 或脚本注入阅读器。

## 当前容量与部署

此版本使用现有 PostgreSQL 保存原件、解析产物和向量，不需要另行部署向量数据库。每文件最多 20 MiB，每库最多 100 个未删除文档；每份文档最多 5000 个切片，检索支持每库最多 10000 个生效切片，同时限制生效向量元素总数不超过 2000000（例如 1024 维时最多 1953 个向量切片）。容量检查在读取向量数据之前执行。解析产物和压缩文件还受解压大小限制。

向量检索使用有界精确余弦计算与关键词排名融合，不是 pgvector/HNSW 近似索引；适用于小规模内部验证。原件与历史版本会占用数据库及备份空间。软删除立即撤销访问，但不会物理清除历史数据；当前没有自动保留期清理或大库索引迁移。扩容前需规划对象存储、数据库容量、历史保留策略与专用向量索引。

升级运行正常迁移链至 `128t_knowledge_base`，只新增知识库表，不修改既有组织和模型数据。后台进程随应用启动，无独立队列依赖。模型用量与结算继续使用已有运行时与计量机制，缺失计量不会当作零费用。
