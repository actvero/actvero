# 知识库

本文面向组织管理员与集成开发者，用于配置解析器和模型、导入资料、检查检索结果，并根据稳定引用定位原文。

## 配置与使用

后台「知识库」提供列表、三步创建、文档处理、检索测试及设置。组织管理员可以管理知识库，成员只能读取使用范围内的资料。使用范围支持仅管理员、组织全员、指定成员与部门；部门规则沿用组织权限服务。

在「默认配置」中选择模型网关已开放的向量模型。模型必须声明向量维度和向量空间，并具备可用渠道和价格。重排序可按需启用。更改模型后自动保存，保存成功后知识库获得组织授权，调用时仍检查任务发起人的知识库权限。模型网关按「知识库索引」与「知识库检索」记录组织用量和金额。直连模型按配置单价核算，New API 调用按网关账单核对。组织知识库用量无需积分换算或个人额度策略。

在「模型网关 → 数据看板」点击「知识库用量」，可按索引、检索或具体模型筛选调用，在详情中查看计量与金额。升级后沿用现有模型配置。历史用量保留原有归属，新增调用纳入组织统计。

通过后台新建的知识库在创建时保存所选检索配置，之后从库内「设置」修改。开启向量或混合检索后，对已有的关键词文档执行「重新处理」以补建向量索引。已有文档使用固定向量空间，更换向量模型时新建知识库后重新导入。此前沿用组织默认重排序的知识库，保存自己的检索配置后使用库级设置。

创建流程为：

1. 填写名称、选填简介并设置使用范围。
2. 选择普通切片或父子切片，并配置结构切分或固定长度切分。普通切片用同一粒度检索和返回。父子切片可分别配置父片和子片长度，用子片召回和重排，返回命中的子片与父片上下文。同一父片只返回一个最佳命中的子片。检索默认采用组织配置，展开「检索配置」可选关键词、向量或混合检索，以及重排模型。混合检索可在「高级设置」调整两路排名权重，默认各占 50%。
3. 选择或拖入文件，然后进入文档列表。选择「跳过上传」可先进入空库，稍后从文档页上传。文档列表支持按文件名、处理状态筛选和按上传时间排序。可在「处理队列」查看异步处理，点击文件名查看原件与切片。

管理员可以在知识库名称旁添加头像，从图标库中选择图标，或上传并裁剪 PNG、JPG、WebP 照片。头像在创建流程、知识库列表和详情同步显示，已设置的头像可移除。

智能切片基于 ENGI 智慧文档结构分组适配，并使用目标字数和边界代价平衡相邻切片，不调用大模型。算法忽略空块与已标识的页眉页脚，优先选择标题前、段落末尾和完整句子的边界，减少短尾片，尽量保持标题与后续正文相邻。长段落沿句子边界切分；单句超长时沿词间空白或标点拆分，必要时按字符截分。完整表格可超过合并软上限，但仍受模型输入硬上限约束。目标字数用于平衡片长，独立短内容、表格及文末片的实际字数可能有差异。每片保留原始块内的字符区间，跨页合并保持全部来源位置。该适配保留独立的 [LGPL 来源与许可](../backend/app/modules/knowledge/licenses/engi-rag-NOTICE.txt)。

长度切片将原文块按顺序连接，以固定字符窗口切分，重叠可跨原文段落；不使用智能模式的目标字数。窗口长度不会超过模型输入上限，重叠长度必须小于窗口；模型上限较小时重叠最多取实际窗口减一。所有长度均按字符计数，不是 Token 数。

父子模式按原文结构或固定长度生成相邻父片。父片不重叠，保留完整上下文，最大长度由父片上限控制。子片在父片内切分，固定长度规则可设子片重叠。子片受模型输入上限约束，原文定位仍使用命中子片的来源区间。

更改库级切片设置只影响后续上传；已有文档需要单独重新处理。算法升级不自动重建已有索引，历史版本与引用继续保留。

创建和设置提供「按标题和段落」「按固定长度」「父子切片」三种方案。标题段落方案默认只需填写目标字数，段落合并软上限随目标按 1.5 倍调整；自定义上限在高级设置中保留。父子方案分别设置父片、子片上限；既有固定长度父子配置仍可在高级设置中查看与修改。

管理员打开文档后，选择「调整切片」，即可用该文档已解析的原文自动试算。预览显示切片总数、平均、最短、最长字数，支持搜索、分页及原文高亮。参数未通过校验或请求失败时不显示旧结果。预览不调用解析或向量服务，也不改动现有切片。点击「应用并重新建立索引」后才创建新处理版本，复用已解析原文；索引成功前保留旧索引。文档版本、参数或模型配置发生变化时需要重新预览。

## 文件与原文定位

| 文件 | 解析方式 | 定位与预览 |
| --- | --- | --- |
| PDF、PNG、JPEG | MinerU 官方云端 API | 页号、原始块及可用坐标；PDF.js 读取原件，支持跳页、缩放与坐标高亮 |
| TXT、Markdown | UTF-8 本地结构解析 | 段落、标题、原始行号；在原文件内容上高亮 |
| CSV | 本地记录解析 | 按记录呈现并高亮表格行；带引号的多行字段属于一条记录 |
| DOCX | OOXML 文本解析 | 按正文顺序显示段落、表格及内嵌 PNG、JPEG 图片，在原段落内高亮文字 |
| XLSX | OOXML 缓存值解析 | 切换工作表，按原行号和列名显示与高亮单元格；公式显示保存时的缓存结果 |

点击切片摘要可查看对应原文，点击摘要右上角的箭头可读完整切片。返回列表会保留搜索与滚动位置。可以拖动分隔线或聚焦后按方向键调整两栏宽度，也可以收起切片栏继续阅读。

原件内容不可修改；每次重新处理创建独立版本。切片保留原文块 ID、块内起止字符、页号或段落、单元格位置，以及跨页的全部来源。PDF 与图片按有效坐标高亮；缺少坐标时，PDF 仍可按页定位。TXT 和 Markdown 的范围按 Unicode 码点计算，结束位置不包含在高亮范围内。PDF 字体和 CMap 随应用打包。DOCX 使用流式排版，复杂格式和分页可能与 Word 不同；XLSX 不重新计算公式。可从文档列表下载原件，以原应用查看完整效果。

旧索引在新版本成功前继续提供检索，历史引用仍指向原版本。删除文档或归档知识库后，所有版本的引用和原文访问立即撤销。原文接口每次重新验证当前权限，响应禁止缓存；不公开文件存储地址。

## MinerU 凭据与任务恢复

PDF 和图片会发送至 MinerU，其他支持格式在服务内解析。在「默认配置 → 文档解析」点击「添加 Key」，可填写名称并用逗号分隔多个官方 Key。批量新增多个 Key 时按名称编号。已有凭据可以从行尾菜单编辑名称或删除。仍有解析任务使用该 Key 时，请等待任务结束后再删除。保存自动去重、加密，读取接口不返回密钥。批次超过总数上限或包含格式错误时整批不写入。请按官方服务权限与配额使用，不同 Key 不代表同账号配额增加。

批量凭据会根据 Token 中可识别的账号标记分组冷却。这些未验证字段仅用于调度，不用于认证或权限判断；无法识别账号时按 Key 分别冷却。旧接口保存的账号分组继续保留。所有 Key 最终均由 MinerU 校验权限及账号配额。

任务选择可用账号凭据。遇到 HTTP 429 时按 `Retry-After` 冷却同账号的所有 Key，随后选择其他可用账号；全部冷却时等待。401/403 会停用对应 Key。已提交的解析任务固定使用原提交凭据继续查询，不会重新创建任务。

解析或索引未完成时统一显示「处理失败」，管理员可从文档操作菜单选择「重试处理」。旧版暂停任务也使用同一失败状态与重试入口，不设置人工核对步骤。提交响应丢失、进程在模型调用期间退出时，后台保留执行标记并停止自动重放；手动重试创建新处理版本，复用已有解析结果，可能重新调用外部服务。没有可用 Key 时任务等待配置。后台任务保存在数据库中，带租约且每阶段超时受限，服务重启后继续处理未完成的确定性步骤。

当前 MinerU 适配器读取官方 ZIP 中的 `*_content_list.json`，按该格式的 0–1000 坐标转换为归一化坐标。无法识别的产物会报错，不会猜测位置。官方契约见 [MinerU API](https://mineru.net/doc/docs/) 与 [产物说明](https://opendatalab.github.io/MinerU/reference/output_files/)。

## 接口与集成边界

完整请求、响应与字段约束见 [OpenAPI](api/openapi.json)，接口前缀 `/api/v1/knowledge`，标签 `knowledge`。

| 功能 | 接口 |
| --- | --- |
| 默认模型与解析凭据 | `GET/PUT /defaults`、`POST /credentials`、`POST /credentials/batch`、`PUT/PATCH/DELETE /credentials/{id}` |
| 知识库管理 | `GET/POST /`、`GET/PUT/DELETE /{base_id}` |
| 知识库头像 | 创建或更新时设置 `icon_selection`；也可用 `PATCH /{base_id}/icon` 单独更换，带当前 `version` |
| 文档上传与列表 | `GET/POST /{base_id}/documents` |
| 文档切片 | `GET /{base_id}/documents/{document_id}` |
| 切片试算 | `POST /{base_id}/documents/{document_id}/chunk-preview`，固定文档版本，返回参数、来源范围、统计与分页结果 |
| 重新处理 | `POST /{base_id}/documents/{document_id}/rebuild` |
| 文档删除 | `DELETE /{base_id}/documents/{document_id}` |
| 原件、阅读定位与解析产物 | 文档路径下的 `GET /source`、`GET /preview`、`GET /parsed-source`；阅读器不展示解析产物 |
| 检索 | `POST /{base_id}/search` |
| 稳定引用 | `GET /{base_id}/citations/{chunk_id}` |

以上管理接口使用 Web 会话；所有写入及检索 POST 需要有效 Origin 与 CSRF。平台运营身份不自动拥有组织资料访问权。上传使用二进制正文与 UUID `upload_id`，同标识同内容重试返回原文档；内容不一致返回冲突。更新设置带 `version`，重建带当前 `generation_id`，避免覆盖并发修改。

检索先限制授权知识库和生效文档，再按库内策略召回并按需重排序。混合检索使用加权倒数排名融合，无可用向量时使用关键词召回。纯向量检索在向量索引建好后返回结果。结果包含实际检索方式、引用 ID、文档 ID、处理版本、来源位置与同源原件接口。父子切片命中另含 `parent_context`，引用 ID 和来源位置仍指向子片。文档列表的 `chunk_structure` 对应最新处理版本，`character_count` 为该版本的解析字符数，尚未计算时为空。通过 API 建库可显式提交 `retrieval`，或提交 `defaults_version` 保存已确认的组织默认配置；两者都省略时沿用旧版默认行为。桌面资源令牌不适用于这些管理接口；宿主服务使用下述显式授权的访问密钥调用。

## 宿主集成与嵌入阅读器

Odoo 等外部系统通过 [应用集成](APPLICATION-INTEGRATIONS.md) 使用应用 Key 创建知识库、上传文档、检索并签发原文阅读凭证。面向成员的个人集成接口前缀为 `/api/knowledge/v1`，使用 `Authorization: Bearer avk_…`。在个人「访问密钥」中新建密钥，选择「知识库检索与原文阅读」并勾选知识库；密钥只拥有所选库的 `read` 与 `invoke`。原有模型/MCP 密钥不会自动扩大到知识库。也可通过密钥 API 分别授予只读与检索权限。

| 接口 | 权限与用途 |
| --- | --- |
| `GET /bases` | `read`；列出授权且当前成员仍可访问的库 |
| `POST /bases/{base_id}/search` | `invoke`；检索，模型用量沿用组织知识库授权 |
| `GET /bases/{base_id}/citations/{chunk_id}` | `read`；返回引用摘要、文件名、处理版本、原文位置 |
| `POST /bases/{base_id}/citations/{chunk_id}/reader-session` | `read`；传入 `parent_origin`，获取短期阅读凭证 |

长期密钥只保存在宿主后端，不传给浏览器。个人密钥按所属成员及密钥范围校验。应用密钥按组织、应用和当前能力校验。宿主应先检查自身用户对资料的访问资格，再返回摘要或阅读凭证。

阅读凭证最多有效 10 分钟，绑定单个文档、引用版本、签发会话或访问密钥及一个宿主来源。接口返回 `viewer_url`、`token`、`expires_at`、`parent_origin` 和协议名。`viewer_url` 不携带凭证；来源必须是 HTTPS origin，本地开发可使用 localhost/回环 HTTP。仅 `/embed/knowledge` 放开匹配来源的 iframe 嵌入，后台页面仍禁止被框架嵌入。

宿主自行设计角标、悬浮卡片、弹窗、侧栏或全屏容器；原文阅读器只提供展示与事件，不改变宿主布局。典型流程：

1. 宿主服务检索并返回引用；客户端据此绘制角标和摘要卡片。
2. 用户点击引用后，宿主服务签发阅读凭证，客户端创建 iframe，地址为返回的 `viewer_url`。
3. 阅读器通过 `postMessage` 发送 `ready`。宿主校验 `event.origin` 与 `event.source`，向该 iframe 发送 `init`，载荷包含短期 `token`。
4. 阅读器调用 `/api/v1/knowledge-reader/manifest` 获取定位与凭证所绑定的切片，再从 `/api/v1/knowledge-reader/source` 读取原件。用户可以打开切片正文。`expand`、`close` 由宿主决定如何处理，`clear` 可主动清空阅读内容。

所有消息包含 `protocol: "actvero.knowledge.v1"`；禁止使用通配符目标来源。宿主初始化代码示意：

```javascript
const viewerOrigin = new URL(grant.viewer_url).origin;
function receive(event) {
  if (event.origin !== viewerOrigin || event.source !== frame.contentWindow) return;
  if (event.data?.protocol !== "actvero.knowledge.v1") return;
  if (event.data.type === "ready") {
    frame.contentWindow.postMessage(
      { protocol: "actvero.knowledge.v1", type: "init", token: grant.token },
      viewerOrigin,
    );
  }
  // expand / close / error 交给宿主容器处理。
}
window.addEventListener("message", receive);
frame.src = grant.viewer_url;
// 宿主销毁容器时移除监听器，并清除内存中的 grant。
```

阅读器不依赖第三方 Cookie；凭证仅在组件内存，HTTP 请求使用 Bearer。原件与定位接口每次重新鉴权；阅读器每 30 秒复核一次，失效后移除内容。退出原签发会话、撤销密钥、调整成员权限或归档资料都会阻止后续读取；已经下载到用户设备的数据无法远程收回。凭证过期或 `reader_unavailable` 时，宿主重新鉴权并签发凭证，不应无限重试旧凭证。

消息类型：宿主发送 `init`、`clear`；阅读器发送 `ready`、`loaded`、PDF 的 `page`、`expand`、`close`、`error`。不接受任意文件 URL、HTML 或脚本注入阅读器。

## 当前容量与部署

此版本使用现有 PostgreSQL 保存原件、解析产物和向量，不需要另行部署向量数据库。每文件最多 20 MiB，每库最多 100 个未删除文档；每份文档最多 5000 个切片，检索支持每库最多 10000 个生效切片，同时限制生效向量元素总数不超过 2000000（例如 1024 维时最多 1953 个向量切片）。容量检查在读取向量数据之前执行。解析产物和压缩文件还受解压大小限制。

向量检索使用有界精确余弦计算与关键词排名融合，不是 pgvector/HNSW 近似索引；适用于小规模内部验证。原件与历史版本会占用数据库及备份空间。软删除立即撤销访问，但不会物理清除历史数据；当前没有自动保留期清理或大库索引迁移。扩容前需规划对象存储、数据库容量、历史保留策略与专用向量索引。

升级时运行 `alembic upgrade head`。升级保留已有知识库、文档处理版本和引用；历史版本的字符数在重新处理前可能为空。后台进程随应用启动，无独立队列依赖。模型用量与结算继续使用已有运行时与计量机制，缺失计量不会当作零费用。
