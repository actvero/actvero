# 公开文档规范

仓库只保存帮助使用者部署、使用、集成和维护产品的长期文档。文档描述当前行为，字段与约束以代码、OpenAPI 和可执行测试相互校验。

## 允许的内容

项目首页、安装和配置指南、当前架构、接口契约、故障处理、贡献规范、第三方来源与许可。测试代码用于验证行为，正常版本发布说明可记录用户可见变化。

## 过程资料

聊天摘录、任务分工、研究流水、进度台账、交接记录和个人验收证据放在仓库外或 `.local/process/`。不要创建公共 archive 目录收集这些材料。必要结论应写入正式指南或测试，不保留形成结论的对话过程。

## 写作格式

一份文档回答一个主题，说明适用范围、操作步骤、权限与失败处理。标题和链接使用稳定名称；示例使用 example.com、合成账号和本机回环地址，不写实际客户、服务器或个人路径。没有运行过的检查不写成已通过。

Markdown、其他说明文档及 docs 下的文件必须列入 `docs/public-documents.json` 并标明用途。新增公开文档时一起维护文档清单，避免过程记录混入。文档检查会验证清单、标题、相对链接和受限内容。

## 提交检查

运行 `make install-hooks` 安装本地提交检查，`make public-check` 检查工作树，`python3 scripts/check-public-content.py --staged` 检查暂存内容。CI 再次执行同一策略和回归测试。

`.gitignore` 只降低误加文件的概率，不能替代实际内容检查。维护者不应通过强制添加、禁用钩子或放宽 CI 来提交过程资料或秘密。
